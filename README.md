# Mini Factory

Тестовое задание на разработку игровой системы машин, добывающих ресурсы. Основной геймплей заключается в развитии машин: игрок может открывать новые машины и улучшать уже доступные, повышая их уровень и скорость добычи ресурсов.

## Запуск проекта

### Запуск в Unity

1. Клонировать репозиторий.
2. Открыть проект через Unity Hub.
3. Использовать указанную выше версию Unity.
4. Открыть основную сцену проекта:
5. Нажать **Play** в Unity Editor.

## Android Build

Для создания Android-билда:

1. Открыть `File → Build Settings`.
2. Выбрать платформу **Android**.
3. Выполнить `Switch Platform`.
4. Проверить настройки `Player Settings`.
5. Установить необходимые параметры подписи и версии приложения.
6. Выбрать `Build` или `Build And Run`.

## Архитектура

Проект построен вокруг нескольких основных систем и принципов разделения ответственности.

### Entrypoint

`Entrypoint` используется как единая точка входа в приложение.
Его задача — выполнить первоначальную инициализацию основных систем и связать необходимые зависимости между ними.
Путь Assets/Scripts/Gameplay/_Root/GameplayEntryPoint

### Machine

`Machine` содержит основную runtime-логику работы машины.
Машина использует конфигурационные данные и текущее состояние для выполнения своих операций.
Конфигурация содержит статические параметры машины, например:

* уровень;
* стоимость открытия;
* скорость производства;
* параметры улучшения;
* параметры boost;
* ограничения offline production.

Runtime-состояние содержит изменяемые во время игры данные.
Разделение конфигурации и состояния позволяет изменять конфигурационные источники независимо от runtime-логики.

### Analytics Provider

Для аналитики используется отдельная абстракция провайдера.
Игровая логика не должна напрямую зависеть от конкретного SDK аналитики.
Вместо этого системы взаимодействуют с интерфейсом провайдера, а конкретная реализация отвечает за отправку событий.

Это позволяет:

* заменить используемый analytics SDK;
* отключить аналитику;
* использовать mock/fake реализацию во время тестирования;
* не связывать gameplay-код с конкретным сервисом аналитики.

### Proxy

Паттерн **Proxy** используется для отделения данных от их непосредственного взаимодействия с остальной системой.
Proxy выступает промежуточным слоем между клиентским кодом и объектом с данными.
Это позволяет контролировать доступ к данным и скрыть детали их внутреннего хранения и изменения.

Основная идея:

Client
  │
  ▼
Proxy
  │
  ▼
Data / State

Благодаря этому клиентский код не получает прямой доступ к изменяемым данным и работает только через определённый публичный интерфейс.

## Unit Tests

Для тестирования используется **Unity Test Framework**.
Основная логика, не требующая Unity runtime, покрывается unit-тестами.
Тесты позволяют проверять поведение систем независимо от визуального представления игры.

Для запуска тестов:

1. Открыть `Window → General → Test Runner`.
2. Выбрать `EditMode` или `PlayMode`.
3. Нажать `Run All`.

Тесты находятся в:
Assets/Scripts/UnitTests/Editor
