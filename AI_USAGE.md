\# Использование AI



\## AI Инструменты



В процессе разработки использовался AI coding agent \*\*Cline\*\* как плагин для \*\*JetBrains Rider\*\*.



\* \*\*Tool:\*\* Cline

\* \*\*IDE:\*\* JetBrains Rider

\* \*\*Model:\*\* DeepSeek V4.1 Flash



\## Задачи, доверенные AI



AI использовался для следующих задач:



\* создание базовых интерфейсов;

\* реализация конфигурационных провайдеров;

\* реализация взаимодействия между UI и игровой логикой;

\* написание unit-тестов;

\* помощь в рефакторинге и улучшении отдельных частей кода.

\## Отклоненные предложения AI



\### MVx архитектура



AI предложил использовать паттерн семейства \*\*MVx\*\* для организации UI и игровой логики.



Данное решение было отклонено, поскольку для текущего небольшого проекта такая архитектура показалась избыточной и привела бы к дополнительной сложности без существенной практической пользы.



Было принято решение оставить более простое взаимодействие UI с игровой логикой, соответствующее масштабу проекта.



\### Лишние UI классы



AI при реализации UI создал дополнительные классы для отдельных UI-элементов, которые не были необходимы для текущей архитектуры.



Эти классы были удалены, а реализация упрощена.



\### Наименование



В процессе разработки также вручную изменялись названия некоторых классов и методов, предложенные AI, чтобы привести их к единому стилю именования проекта и точнее отражать их ответственность.



\## Ошибки AI



AI в процессе разработки допускал решения, которые требовали дополнительной проверки и корректировки.



Основные случаи:



\* создание избыточных классов для UI;

\* предложение использовать MVx-архитектуру, которая была признана избыточной для данного проекта;

\* необходимость корректировки имен классов и методов;

\* адаптация сгенерированного кода под уже выбранную архитектуру проекта.



AI использовался как инструмент разработки и источник предложений, однако окончательные технические решения, архитектура и интеграция кода выполнялись и проверялись самостоятельно.
